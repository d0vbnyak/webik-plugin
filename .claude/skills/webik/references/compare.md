# Сравнение «было / стало»

Страница для клиента: скриншоты старого и нового сайта, оценки Lighthouse, скорость и список исправленного. Живёт на демо по адресу `<demo_url>/sravnenie/`, её ссылку отправляют вместе с коммерческим предложением.

Нужны Node.js (npx) и установленный Google Chrome. Если чего-то нет, скажи пользователю и продолжай этап без сравнения: это дополнение, а не условие.

Данные лежат в `.webik/compare/`:

```
.webik/compare/
├── before/     # снимок старого сайта (этап аудита)
├── after/      # снимок демо-версии (этап демо)
└── fixed.md    # что исправлено, языком клиента
```

## Снимок «было» — на этапе аудита

Старый сайт может скоро смениться или исчезнуть, поэтому снимок делается сразу, на аудите:

```bash
bash "<папка скилла>/scripts/capture.sh" <url старого сайта> .webik/compare/before
```

Скрипт снимает главную страницу: скриншоты desktop (1440) и mobile (iPhone 13) во всю длину и три прогона Lighthouse для мобильных, из которых потом берётся медиана. Занимает 2–4 минуты.

## Список исправленного — на этапе сборки

После сборки запиши `.webik/compare/fixed.md`: по одному пункту на строку, начиная с `- `. Источник — раздел «Главные проблемы» брифа и то, что реально сделано.

Пиши для владельца бизнеса, а не для разработчика:

- «Сайт удобно открывается на телефоне: раньше текст был мелким и уезжал за край экрана», а не «добавлен адаптив, viewport»;
- «У каждой страницы своё название и описание в поиске Яндекса и Google», а не «уникальные title/description»;
- «Старые ссылки на сайт продолжают работать и ведут на новые страницы».

Только то, что действительно исправлено. Без штампов (`references/anti-ai.md`) и без технических терминов. 5–10 пунктов, самые заметные для клиента — первыми.

## Снимок «стало» и страница — на этапе демо

После выкладки на демо (`references/deploy.md`):

1. Снимок демо-версии:
   ```bash
   bash "<папка скилла>/scripts/capture.sh" <demo_url> .webik/compare/after
   ```
   Мерить нужно именно демо на сервере, а не локальное превью: старый сайт тоже мерился через интернет.
2. Страница сравнения в демо-сборку:
   ```bash
   node "<папка скилла>/scripts/compare-page.mjs" .webik/compare dist --title "<Название компании>"
   ```
   SEO обеих версий считается без аудита индексации: демо закрыто от поиска, на боевом сайте запрет снимется. Это сказано и в сноске страницы.
3. Повторная выкладка с той же проверкой демо-сборки: `bash "<папка скилла>/scripts/deploy-demo.sh" <slug> dist`.
4. Открой `<demo_url>/sravnenie/` и проверь: цифры на месте, скриншоты грузятся, переключатель «Компьютер / Телефон» работает.
5. Запиши в `state.json` → `compare_url`.

Если какая-то оценка «стало» ниже, чем «было», не скрывай её. Разберись в причине по отчёту Lighthouse из `.webik/compare/after/`, исправь сайт и повтори снимок. Если исправить нельзя (например, тяжёлый виджет, который клиент требует оставить), скажи об этом пользователю.

## Контакты студии на странице

Подвал страницы берёт контакты студии из `~/.webik/config.json`, блок `studio`. Блок необязателен, без него подвала нет:

```json
{
  "studio": {
    "name": "Webik",
    "phone": "+7 900 000-00-00",
    "telegram": "@webik_studio",
    "email": "hello@webik.ru",
    "site": "https://webik.ru"
  }
}
```

Значения не придумываются: если блока нет, оставь страницу без подвала.
