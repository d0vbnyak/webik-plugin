# Сравнение «было / стало»

Страница для клиента — **главная демо-версии**: `https://<slug>-demo.webik.tech/`. Сам новый сайт на демо живёт на `/glavnaya/`. В боевой сборке страницы сравнения нет, главная сайта на `/`. Ссылку на демо отправляют вместе с коммерческим предложением.

На странице: шапка с проверенными цифрами и ссылками на новый и старый сайт, **слайдеры «было / стало»** по первым экранам ключевых страниц, блоки «проблема → что сделано» по темам, «что нужно от вас до запуска». Образец — `templates/compare/` в плагине (утверждённая версия «Аквамарина»).

Нужен Node.js (npx). Playwright ставит Chromium и WebKit сам. Google Chrome — только для Lighthouse.

## 1. Снимок «было» — на этапе аудита

Старый сайт может скоро смениться или исчезнуть, поэтому снимок делается сразу. Страницы — главная и по одной странице-образцу ключевых типов (те же, что пойдут в макет):

```bash
bash "<папка скилла>/scripts/capture.sh" https://старый-сайт.ru .webik/compare/before home=/ tour=/moneron catalog=/zimnie
```

Каждая страница снимается первым экраном на компьютере (окно 1280×800, файл 2560×1600) и на телефоне (iPhone 13 mini, 375×812, файл 1125×2436), плюс сохраняется её HTML. Скриншоты панели браузера для этого не годятся: они мелкие и пережатые, на слайдере выходят мутными.

`WEBIK_LH=1` перед командой добавит три прогона Lighthouse главной — если хочется цифр скорости.

## 2. Список проблем и исправлений — на этапе сборки

После сборки запиши группы «проблема → что сделано» в `src/data/compare.ts` (поле `groups`, формат — `templates/compare/compare.example.ts`). Источник — раздел «Главные проблемы» брифа и то, что реально сделано.

- Группы по темам, по убыванию влияния на заявки: «Заявки и доверие», «Навигация и выбор», «Поиск в Яндексе и Google», «Телефон и скорость», «Узнаваемость».
- Каждая строка: слева «Было» — конкретная проблема с доказательством (адрес, цифра, цитата), справа «Стало» — что сделано.
- Пиши для владельца бизнеса: «С телефона нельзя было дозвониться: в ссылке не хватало цифры», а не «некорректный href tel:».
- Только то, что действительно исправлено и проверено. Без штампов (`references/anti-ai.md`).
- Пункты о правах на фото не добавлять.

## 3. Снимок «стало» и страница — на этапе демо

1. Выложи демо (`references/deploy.md`), затем сними **демо на сервере** — те же имена страниц, новые пути:
   ```bash
   bash "<папка скилла>/scripts/capture.sh" https://<slug>-demo.webik.tech .webik/compare/after home=/glavnaya/ tour=/moneron/ catalog=/zimnie/
   ```
   Мерить нужно демо на сервере, а не локальное превью: старый сайт тоже снимался через интернет. При самой первой выкладке `/glavnaya/` ещё нет — сначала выложи демо с компонентом сравнения на заглушечных данных, сними, потом обнови.
2. Цифры для шапки:
   ```bash
   node "<папка скилла>/scripts/compare-facts.mjs" --before .webik/compare/before --after .webik/compare/after --dist dist --redirects deploy/redirects.nginx.conf
   ```
   Считает: страницы в сборке, правила 301 и 410, сторонние скрипты по страницам (было / стало, включая встроенные счётчики), Lighthouse, если снимали. Пишет `.webik/compare/facts.json`. В шапку идут **только** эти цифры и факты из брифа.
   - Сторонние скрипты: если на проде будут счётчики (Метрика, Analytics), пиши честно: «20 → 2: остались только счётчики посещений», а не «20 → 0».
   - Правила ≠ адреса: одно правило с регулярным выражением закрывает много адресов. Число «старых адресов с перенаправлением» бери из `check-site.mjs` (карта URL), а не из числа правил.
3. Подключи страницу в проект (один раз):
   - `src/components/demo/Comparison.astro` ← `templates/compare/Comparison.astro`; переменные `--cmp-*` в начале замени на токены и шрифты сайта (импортируй fontsource-шрифты сайта в компоненте).
   - `src/data/compare.ts` ← по образцу `compare.example.ts`: заголовок, лид, цифры, пары скриншотов с пояснениями «было / стало», группы, «нужно от вас».
   - Скриншоты: `.webik/compare/{before,after}/<имя>-<desktop|mobile>.png` → `src/assets/compare/{before,after}-<имя>-<desktop|mobile>.png`.
   - «Что нужно от вас» — из предупреждений `check-site.mjs` (заглушки `[НУЖНО ОТ ВАС]`), сгруппированных и сформулированных для клиента.
4. Демо-маршрутизация (см. `references/astro-stack.md` → «Демо и боевая сборка»):
   - `src/pages/index.astro`: на демо — `Comparison`, на проде — главная сайта;
   - `/glavnaya/` — главная сайта, только в демо-сборке;
   - все ссылки «на главную» (логотип, хлебные крошки, 404) — через `homeHref`.
5. Демо-сборка, `check-site.mjs`, выкладка `deploy-demo.sh`, затем боевая сборка обратно в `dist/`.
6. Открой `<demo_url>/` и проверь: слайдеры двигаются мышью и стрелками, скриншоты резкие, на ширине 375 нет горизонтальной прокрутки, «Открыть новый сайт» ведёт на `/glavnaya/`.

Если цифра «стало» хуже, чем «было», не прячь её: разберись в причине, исправь сайт и пересними.

## Подписи к парам

- Пара — одна страница на одном устройстве. Обычно 3–5 пар: главная на компьютере и телефоне, ключевой шаблон (тур, услуга, товар) и каталог.
- `alt` каждой картинки описывает, что видно на кадре.
- Пояснение «было» — что на кадре мешает посетителю; «стало» — что изменилось. 1–2 предложения, факты с кадра.
