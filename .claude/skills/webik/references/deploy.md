# Этап 4 — Демо-сервер и подготовка к проду

- **Демо** — сюда выкладываются все готовые редизайны. У каждого проекта свой адрес и своя папка: `url_template` с подставленным `slug` (сейчас `https://<slug>-demo.webik.tech/`) → `<root>/<slug>/`. Выкладывает Claude командой `/webik:demo`.
- **Прод** — сайты клиентов, которые оплатили работу. Выкладывает **только руководитель вручную**. Claude на прод клиента не деплоит, даже если попросят: он готовит `DEPLOY.md` и `dist/`.

## Конфиг демо-сервера

Файл на машине сотрудника: `~/.webik/config.json` (в Windows `C:\Users\<имя>\.webik\config.json`). Другой путь можно задать переменной `WEBIK_CONFIG`.

```json
{
  "demo": {
    "host": "72.56.237.147",
    "port": 22,
    "user": "root",
    "root": "/var/lib/docker/volumes/sakhuslugi_caddy_data/_data/demo",
    "url_template": "https://{slug}-demo.webik.tech",
    "caddy": {
      "container": "sakhuslugi-caddy-1",
      "caddyfile": "/opt/sakhuslugi/site/deploy/Caddyfile",
      "caddyfile_in_container": "/etc/caddy/Caddyfile",
      "root_in_container": "/data/demo",
      "backup_dir": "/opt/sakhuslugi/site/deploy/backup",
      "check_urls": ["https://sakhuslugi65.ru/", "https://webik.tech/"]
    }
  }
}
```

- `url_template` — обязательно с `https://` и `{slug}`; другой заполнитель (`{sitename}`) скрипт не примет.
- Блок `caddy` нужен, когда демо раздаёт Caddy в Docker и каждому проекту нужен свой блок в Caddyfile (так сейчас устроено: демо живут на сервере sakhuslugi). Без блока `caddy` скрипт только кладёт файлы — так работает схема с nginx и wildcard (`docs/demo-server.md`).
- `check_urls` — соседние сайты на том же сервере: скрипт проверяет их до и после перезагрузки Caddy и откатывает изменения, если какой-то перестал отвечать.

Если файла нет или в нём не хватает полей, не придумывай значения: скажи пользователю, что заполнить, и покажи пример. Доступ — по SSH-ключу; пароли в конфиг не пишутся.

**Ключ на сервер (один раз).** В PowerShell нет `ssh-copy-id`. Команда, которая один раз спросит пароль и допишет ключ:

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub" | ssh root@<host> "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

Проверка: `ssh -o BatchMode=yes root@<host> "echo ok"`. В Git Bash, Linux и macOS — `ssh-copy-id -i ~/.ssh/id_ed25519.pub root@<host>`.

## Выкладка на демо

1. Прочитай `state.json`: нужен `slug`, `stage` не ниже `built`. Если сайт не собран, сначала этап сборки.
2. Адрес проекта: `url_template` с подставленным `slug`.
3. **Проверка сервера перед первой выкладкой проекта** (только чтение): вход по ключу (`ssh -o BatchMode=yes … "echo ok"`), есть ли `root`, есть ли контейнер и Caddyfile из блока `caddy`, указывает ли DNS адрес демо на этот сервер (`nslookup <адрес> 8.8.8.8`). Если что-то не сходится с конфигом — остановись и опиши, что нашёл. Ничего на сервере руками не настраивай.
4. Демо-сборка с адресом демо (переменная нужна для canonical, sitemap и OG):
   - bash: `WEBIK_DEMO_URL=<адрес> npm run build:demo`
   - PowerShell: `$env:WEBIK_DEMO_URL='<адрес>'; npm run build:demo`
5. `node "<папка скилла>/scripts/check-site.mjs" dist` — ошибок быть не должно; демо-сборка без `noindex` считается ошибкой.
6. Выкладка скриптом из папки скилла:

   ```bash
   bash "<папка скилла>/scripts/deploy-demo.sh" <slug> dist
   ```

   Скрипт проверяет slug, шаблон адреса и демо-сборку, загружает архив и атомарно подменяет папку проекта: старая версия работает до последнего момента. С блоком `caddy` для нового проекта он сам: делает резервную копию Caddyfile, дописывает блок сайта (только через `cat >>`: файл примонтирован в контейнер), проверяет `caddy validate`, плавно перезагружает Caddy, проверяет `check_urls` и при любой ошибке возвращает Caddyfile как было. Повторная выкладка Caddyfile не трогает.

   Если защита Claude Code блокирует запуск скрипта (запись на удалённый сервер), не обходи её: скажи пользователю, какое правило разрешения добавить (README плагина, раздел «Права»), или дай команду, чтобы он выполнил её сам.
7. Проверка: `curl -sI <адрес>` → `200`, несуществующий адрес → `404`, заголовок `X-Robots-Tag: noindex`; открой главную и одну внутреннюю страницу браузерным инструментом. Если локальный DNS ещё не видит новый адрес — `curl --resolve <host>:443:<ip>`.
8. Страница сравнения «было / стало» по `references/compare.md` → «Снимок «стало» и страница». Если снимка «было» нет (`.webik/compare/before/`), сделай его сейчас, пока старый сайт работает.
9. Обнови `state.json`: `stage: "demo"`, `demo_url`, `compare_url`, `updated`. Ответь ссылкой на демо.
10. После выкладки верни в `dist/` боевую сборку (`npm run build`), чтобы `DEPLOY.md` и `dist/` не расходились.

Повторная выкладка того же проекта перезаписывает его демо-версию. Другие проекты на сервере не затрагиваются.

**Сервер sakhuslugi.** Caddyfile на сервере — копия из репозитория sakhuslugi. Блоки демо, которые дописывает скрипт, нужно переносить в этот репозиторий, иначе следующий деплой sakhuslugi их сотрёт. Напоминай об этом в отчёте, когда добавлен новый блок.

## Прод: DEPLOY.md

На этапе сборки создай в корне проекта `DEPLOY.md` для руководителя. Заполни реальными данными проекта, ненужные пункты удали:

```markdown
# <Название> — выкладка на прод

Домен: <домен>, Главное зеркало: https://<с www или без>, Сборка: <дата>

## Сборка
npm ci
npm run build        # результат в dist/

## Переменные окружения (.env перед сборкой)
| Переменная | Назначение | Значение |
|---|---|---|
| PUBLIC_FORM_ENDPOINT | обработчик форм | ? |
| PUBLIC_YM_ID | Яндекс Метрика | ? |

## Сервер
- Загрузить содержимое dist/ в корень сайта.
- nginx: `try_files $uri $uri/ =404;`, `error_page 404 /404.html;`.
- Подключить `deploy/redirects.nginx.conf` внутри server-блока (301 со старых URL).
- 301 с http → https и с неосновного зеркала (www/без www) на основное.
- Кэширование: `/_astro/` — `Cache-Control: public, max-age=31536000, immutable`.
```
