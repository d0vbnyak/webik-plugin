# Этап 4 — Демо-сервер и подготовка к проду

У студии два VPS:

- **Демо** — сюда выкладываются все готовые редизайны. У каждого проекта свой поддомен и своя папка: `https://<slug>.<демо-домен>/` → `<root>/<slug>/`. Выкладывает Claude командой `/webik:demo`.
- **Прод** — сайты клиентов, которые оплатили работу. Выкладывает **только руководитель вручную**. Claude на прод не деплоит, даже если попросят: он готовит `DEPLOY.md` и `dist/`.

## Конфиг демо-сервера

Файл на машине сотрудника: `~/.webik/config.json` (в Windows `C:\Users\<имя>\.webik\config.json`). Другой путь можно задать переменной `WEBIK_CONFIG`.

```json
{
  "demo": {
    "host": "203.0.113.10",
    "port": 22,
    "user": "deploy",
    "root": "/var/www/demo",
    "url_template": "https://{slug}.demo.example.ru"
  }
}
```

Если файла нет, не придумывай значения: скажи пользователю, какой файл создать, и покажи пример выше. Доступ — по SSH-ключу пользователя; пароли в конфиг не пишутся.

## Выкладка на демо

1. Прочитай `state.json`: нужен `slug`, `stage` не ниже `built`. Если сайт не собран, сначала этап сборки.
2. Адрес проекта: `url_template` с подставленным `slug`.
3. Демо-сборка с адресом демо (переменная нужна для canonical, sitemap и OG):
   - bash: `WEBIK_DEMO_URL=<адрес> npm run build:demo`
   - PowerShell: `$env:WEBIK_DEMO_URL='<адрес>'; npm run build:demo`
4. Проверь, что сборка действительно демо: `dist/robots.txt` содержит `Disallow: /`, а в `dist/index.html` есть `noindex`. Если нет — **не выкладывай**, исправь сборку.
5. Выкладка скриптом из папки скилла:

   ```bash
   bash "<папка скилла>/scripts/deploy-demo.sh" <slug> dist
   ```

   Скрипт проверяет slug и демо-сборку, загружает архив и атомарно подменяет папку проекта на сервере: старая версия работает до последнего момента.
6. Проверка: `curl -sI <адрес>` → `200`; открой главную и одну внутреннюю страницу (браузерным инструментом, если он есть).
7. Страница сравнения «было / стало» по `references/compare.md` → «Снимок «стало» и страница». Если снимка «было» нет (`.webik/compare/before/`), пропусти шаг и скажи об этом.
8. Обнови `state.json`: `stage: "demo"`, `demo_url`, `compare_url`, `updated`. Ответь двумя ссылками: демо-сайт и страница сравнения.

Повторная выкладка того же проекта перезаписывает его демо-версию. Другие проекты на сервере не затрагиваются.

## Прод: DEPLOY.md

На этапе сборки создай в корне проекта `DEPLOY.md` для руководителя. Заполни реальными данными проекта, ненужные пункты удали:

```markdown
# <Название> — выкладка на прод

Домен: <домен>, Главное зеркало: https://<с www или без>, Сборка: <дата>

## Сборка
npm ci
npm run build        # результат в dist/

## Переменные окружения (.env перед сборкой)
| Переменная | Назначение | Значение |
|---|---|---|
| PUBLIC_FORM_ENDPOINT | обработчик форм | ? |
| PUBLIC_YM_ID | Яндекс Метрика | ? |

## Сервер
- Загрузить содержимое dist/ в корень сайта.
- nginx: `try_files $uri $uri/ =404;`, `error_page 404 /404.html;`.
- Подключить `deploy/redirects.nginx.conf` внутри server-блока (301 со старых URL).
- 301 с http → https и с неосновного зеркала (www/без www) на основное.
- Кэширование: `/_astro/` — `Cache-Control: public, max-age=31536000, immutable`.

## Формы
Какие формы есть на сайте, какие поля отправляют, куда должны приходить заявки.

- [ ] Удалить демо-версию или закрыть её паролем (по желанию)
```
