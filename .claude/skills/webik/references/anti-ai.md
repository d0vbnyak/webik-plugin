# Запрещённые признаки AI-работы

Сайт не должен выглядеть и читаться как сгенерированный. Всё ниже **запрещено** на этапах макета и сборки. У каждого пункта есть замена: запрет без замены толкает к другому шаблону.

Исключение одно: элемент действительно есть у клиента (зарегистрированный слоган, фирменный шрифт, настоящая статистика из старого сайта). Тогда он остаётся, а в `design.md` записывается, откуда он взялся.

Если сомневаешься, признак это или решение, считай признаком и переделай.

## Тексты

### Штампы

Запрещены фразы и их вариации:

- «Мы — команда профессионалов», «команда опытных специалистов»
- «индивидуальный подход к каждому клиенту», «мы ценим каждого клиента»
- «широкий спектр услуг», «полный комплекс услуг»
- «динамично развивающаяся компания», «лидер рынка» (без доказательств)
- «ваш надёжный партнёр», «качество, проверенное временем»
- «оптимальное соотношение цены и качества», «доступные цены», «лучшие цены»
- «в кратчайшие сроки», «быстро и качественно»
- «Добро пожаловать на наш сайт», «Ваш комфорт — наш приоритет»
- «Откройте для себя…», «Погрузитесь в мир…», «Раскройте потенциал…», «новый уровень»
- «инновационные решения», «уникальный», «премиальный», «идеальный выбор» без конкретики
- «Мы делаем X, чтобы вы могли Y» как формула каждого абзаца

**Замена:** конкретный факт со старого сайта. Не «опытные специалисты», а «12 мастеров, у бригадиров стаж от 8 лет», если это есть в данных. Если фактов нет, напиши проще и короче, а в брифе задай вопрос клиенту.

### Конструкции

- **«Не просто X, а Y»** («Не просто ремонт — пространство для жизни») → прямое утверждение: «Ремонт квартир с дизайн-проектом».
- **Тройки везде** («быстро, надёжно, честно», три прилагательных, три пункта в каждом блоке) → столько пунктов, сколько есть по факту.
- **Рубленые фразы с точками** («Быстро. Надёжно. Честно.») → одно полное предложение.
- **Разделители «·», «•», «|» между словами** → запятые, настоящий список или разделитель через CSS (подробно в `references/seo.md` → «Пунктуация и разделители»).
- **Риторические вопросы в заголовках** («Ищете надёжного подрядчика?», «Устали от некачественного ремонта?») → утверждение с сутью предложения.
- **Формула «Тема: обещание»** в каждом заголовке («Ремонт: просто и удобно») → обычный заголовок со смыслом.
- **Тире в каждом предложении** → не больше одного тире на абзац, остальное запятыми и точками.
- **Восклицательные знаки** → убрать.
- **Эмодзи и галочки** (✅ ✨ 🚀 ✓) в заголовках, кнопках, списках и текстах → убрать; маркеры списков задаются стилем.
- **Английские слова** в русском интерфейсе («Get started», «Learn more», «Hero») → по-русски.
- **Заглавная Буква В Каждом Слове** заголовка → обычный регистр.

### Шаблонные блоки и призывы

- «Почему выбирают нас» с абстрактными достоинствами → блок с конкретными фактами (гарантия в договоре, свой склад, выезд замерщика в день звонка), а если фактов нет, блока нет.
- «Наша миссия», «Наши ценности» без содержания → убрать или заменить историей компании из данных.
- Кнопки «Подробнее», «Узнать больше», «Начать», «Отправить» → глагол с результатом: «Рассчитать стоимость», «Записаться на замер», «Получить прайс».
- Придуманный FAQ → только вопросы, на которые есть ответы в данных клиента.

### Выдуманный контент

Строго запрещено, без исключений:

- цифры («500+ клиентов», «98% довольных», «10 лет на рынке»), если их нет на старом сайте;
- отзывы, имена и фото клиентов, кейсы;
- логотипы партнёров, награды, сертификаты, членство в ассоциациях;
- сотрудники, должности, фото команды;
- адреса, телефоны, e-mail, реквизиты (никаких `info@example.com`, `+7 (999) 000-00-00`);
- lorem ipsum и «текст-рыба».

**Замена:** видимая заглушка `[НУЖНО ОТ ВАС: отзывы]` и вопрос в брифе.

## Визуал

- **Hero с градиентом, пятнами, «стеклом» (glassmorphism), сеткой точек или шумом** на фоне → настоящее фото клиента или композиция из бренда.
- **Фиолетово-синие и неоновые градиенты, градиентный текст в заголовках** → цвет из бренда клиента, сплошной.
- **Плашка над заголовком hero** («✨ Новое», «🔥 Акция», пилюля с иконкой) → убрать; если акция реальная, отдельный блок.
- **Подпись-«кикер» капсом над каждым заголовком секции** → только там, где она несёт информацию (номер этапа, раздел каталога), не больше чем у пары секций.
- **Три одинаковые карточки «иконка в цветном квадрате, заголовок, две строки»** → композиция под содержание: список с цифрами, таблица, фото с подписью, шаги.
- **Иконка у каждого пункта** → иконки только там, где они помогают узнать пункт быстрее.
- **Полоса статистики «500+ / 10 лет / 98%»** → только реальные цифры, иначе блока нет.
- **Карусель отзывов, облако логотипов, бенто-сетка** без реального содержания → убрать.
- **Всё по центру** → выравнивание по левому краю для текста; центр только для коротких акцентов.
- **Одинаковые отступы и фоны у всех секций, бесконечное чередование «фото слева — фото справа»** → ритм секций (`references/design-craft.md`).
- **Огромные скругления на всём, мягкие тени на всём** → шкала скруглений и одна стратегия глубины.
- **Декоративные плавающие фигуры, иконка «мышки» для скролла, бегущая строка, hero на 100vh** с одной фразой → убрать; первый экран показывает суть и действие.
- **Карточки, которые увеличиваются при наведении** (`hover:scale-105`), анимация `bounce`/`pulse` для украшения → тонкая смена цвета или тени, анимация только со смыслом.
- **Тёмная тема без запроса** → светлая, если бренд не требует иного.
- **Шрифты по умолчанию и моноширинные** (Inter, Montserrat, Open Sans, JetBrains Mono, Space Mono…) → шрифт под бизнес (`references/design-craft.md` → «Выбор шрифта»).
- **Стоковые фото «улыбающиеся люди в касках», наборы иллюстраций в одном стиле (unDraw и т. п.), 3D-иконки** → фото клиента в единой обработке.
- **Эмодзи вместо иконок** → SVG-иконки или без иконок.

## Код

- **Одна и та же длинная строка Tailwind-классов** на многих элементах → компонент.
- **Произвольные значения** (`p-[17px]`, `text-[#3a3a3a]`) → токены и шкала.
- **`transition-all`** → конкретные свойства.
- **`href="#"`, пустые ссылки, кнопки без действия** → настоящий адрес или убрать элемент.
- **`<div onclick>` вместо `<button>`/`<a>`** → нативный элемент.
- **Комментарии, которые пересказывают код** (`<!-- Hero section -->`, `// Кнопка`) → без комментариев; комментарий только там, где непонятно *почему*.
- **`console.log`, закомментированный код, неиспользуемые компоненты и зависимости** → удалить.

## Проверка

1. Перед передачей макета: пройди весь список глазами по каждому артборду.
2. После сборки: запусти скрипт из папки скилла, он находит то, что можно поймать автоматически:

   ```bash
   bash "<папка скилла>/scripts/check-ai-tells.sh" src
   ```

   Скрипт выводит файл, строку и правило. Каждое срабатывание исправь или, если это настоящий элемент клиента, запиши исключение в `design.md`.
3. Скрипт не видит композицию, штампы в новых формулировках и выдуманные факты. Их проверяешь ты: перечитай тексты всех страниц на предмет штампов и сверь каждую цифру и каждый факт с `.webik/content/`.
