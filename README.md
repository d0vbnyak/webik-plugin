# Webik

Внутренний плагин Claude Code для реконструкции сайтов. Даёте ссылку на старый сайт и получаете современный сайт на **Astro + Tailwind** с нормальным SEO, выложенный на демо-сервер.

## Как устроена работа

```
ссылка ──► /webik:audit ──► /webik:design ──► Claude Design ──► «закончили» ──► /webik:demo
            бриф,            макет на           команда          /webik:build     демо-сервер
            контент,         холсте Claude      дорабатывает     сайт на Astro
            карта URL        Design             дизайн
```

| Шаг | Что делаете вы | Что делает Claude |
|---|---|---|
| 1 | `/webik:audit https://старый-сайт.ru` | Обходит сайт, скачивает тексты и картинки, находит проблемы, пишет бриф и карту старых и новых URL |
| 2 | `/webik:design` | Создаёт артефакт Claude Design: главная и по одному шаблону на каждый тип страницы, desktop и mobile, с настоящим контентом |
| 3 | Дорабатываете дизайн в Claude Design | — |
| 4 | Пишете «закончили» (или `/webik:build`) | Читает итоговую версию холста и собирает **все** страницы сайта по шаблонам: SEO, микроразметка, sitemap, 301-редиректы, формы |
| 5 | `/webik:demo` | Собирает закрытую от индексации демо-версию и выкладывает её на `https://<проект>.demo.<домен>/` |
| 6 | Клиент оплатил → вы выкладываете на прод сами | Заранее готовит `DEPLOY.md` и `dist/` |

Команды можно не вызывать: Claude понимает и обычные фразы («вот сайт, переделай», «закончили», «выложи на демо»), если в папке проекта есть `.webik/`.

Дополнительно:
- `/webik:design-review` — строгое ревью дизайна собранного сайта, со сверкой с макетом;
- `/webik:design-deslop` — быстро убрать признаки «сгенерированного» дизайна.

## Правила, которые Claude соблюдает

- **Тексты:** смысл, факты, цены и контакты не меняются; заголовки, структура, meta и alt переписываются под SEO.
- **Ничего не выдумывается:** отзывов, цифр, логотипов партнёров нет на старом сайте → видимая заглушка `[НУЖНО ОТ КЛИЕНТА: …]` и вопрос в брифе.
- **Позиции в поиске:** каждый старый URL сохраняется или получает 301.
- **Демо не индексируется:** `noindex`, `Disallow: /` и заголовок `X-Robots-Tag` на сервере.
- **Прод только вручную:** Claude на продакшн-сервер не выкладывает.
- **Код только с Context7:** перед любым кодом сайта Claude проверяет, что подключён MCP-сервер Context7, и пишет по актуальной документации Astro и Tailwind. Без Context7 он останавливается и не пишет код.
- **152-ФЗ:** у форм с персональными данными есть согласие и политика конфиденциальности (заготовка, проверяет юрист клиента).

## Установка

### Через marketplace Claude Code

```bash
/plugin marketplace add d0vbnyak/webik-plugin
/plugin install webik@webik
```

Перезапустите Claude Code. Команды будут доступны как `/webik:audit`, `/webik:design` и т. д. В Claude Code 2.1.275 и новее можно одной строкой: `/plugin install webik --marketplace d0vbnyak/webik-plugin`.

Репозиторий приватный: у сотрудника должен быть доступ к нему на GitHub (`gh auth login` или git-учётка).

Обновление у сотрудников: `/plugin marketplace update webik`. Новая версия подхватывается, только если в манифесте изменилось поле `version`; хук `.githooks/pre-commit` меняет его при каждом коммите. Включается один раз в клоне репозитория: `git config core.hooksPath .githooks`.

### Что нужно на машине сотрудника

- **Node.js** LTS (для Astro);
- `ssh` и `scp` с ключом к демо-серверу (в Windows 10/11 есть встроенный OpenSSH);
- Git Bash в Windows (скрипт выкладки написан на bash);
- вход в claude.ai в Claude Code: без него недоступен артефакт Claude Design;
- **Context7** — подключается вместе с плагином (`.mcp.json`), отдельно ставить не нужно. Проверка: `/mcp` → `context7` в статусе connected. Если сервер не подключился: `claude mcp add --transport http context7 https://mcp.context7.com/mcp`. Без ключа лимиты запросов ниже; бесплатный ключ берётся на context7.com;
- конфиг демо-сервера `~/.webik/config.json` — см. [docs/demo-server.md](docs/demo-server.md#5-конфиг-на-машине-сотрудника).

### Демо-сервер

Однократная настройка (DNS, пользователь, wildcard-сертификат, nginx) — в [docs/demo-server.md](docs/demo-server.md).

## Проект клиента

Каждый сайт — отдельная папка, Claude создаёт её сам при аудите:

```
<slug>/
├── .webik/          # бриф, контент, исходники старого сайта, дизайн-система, состояние
├── src/             # Astro-проект
├── deploy/          # redirects.nginx.conf для прода
├── DEPLOY.md        # инструкция для выкладки на прод
└── package.json
```

## Устройство плагина

```
.claude-plugin/           # манифест плагина и marketplace
.mcp.json                 # MCP-сервер Context7, ставится вместе с плагином
.claude/commands/         # команды /webik:* — тонкие обёртки над процедурами скилла
.claude/skills/webik/
├── SKILL.md              # общий поток, правила, распознавание этапа
├── references/           # процедуры этапов и справочники (аудит, Claude Design, сборка, Astro, SEO, деплой, дизайн)
└── scripts/deploy-demo.sh
docs/demo-server.md       # настройка демо-сервера
```

Процедуры этапов лежат в `references/` и одинаково используются и командами, и обычными запросами. Чтобы поменять поведение этапа, правьте соответствующий файл в `references/`.
